# Architecture

## Service Wiring (Go)

Wire DI flow: `internal/app/wire.go` declares providers → `wire gen ./internal/app/` writes `wire_gen.go` → `main.go` calls `app.InitializeApp(wailsApp)`.

Services registered with Wails (callable from JS via `main.go:60-73`):
- `Settings`, `Welcome`, `Clipboard` — via Wire-injected `App` struct
- `EnhanceService` — wraps `Settings` for AI calls
- `LoggerService` — forwards frontend log messages to `debug.log`
- `UpdaterService` — version check + GitHub Releases API
- `simulateService` — local struct in `main.go`, exposes `SimulateShortcut` for dev-tools
- Registration pattern: `wailsApp.RegisterService(application.NewService(svc))`

After adding or changing a Go service method signature: run `wire gen ./internal/app/` then `wails3 generate bindings`. Both steps are required — Wire for DI, bindings for the JS RPC layer.

## RPC Bridge

`frontend/src/app/core/wails.service.ts` is the single point of contact between Angular and Go. It imports from `frontend/bindings/` (auto-generated). All components depend on `WailsService`, never on bindings directly.

Browser mode: `wails.service.ts` detects when the Wails runtime is absent (Playwright / `ng serve`) and returns `BROWSER_MODE_DEFAULTS` for settings and "not installed" for the Claude Code status. There is no provider fallback in the frontend — `TextEnhancementService` passes straight through to `WailsService`, so nothing under `frontend/src` calls a provider (#87).

## Key Management

Priority chain (checked in this order): environment variable → OS keyring (`go-keyring`) → empty string.

Env var mapping (`internal/features/settings/service.go`):
- `openai` → `OPENAI_API_KEY`
- `claude` → `ANTHROPIC_API_KEY`
- `openrouter` → `OPENROUTER_API_KEY`
- `bedrock` → `AWS_BEARER_TOKEN_BEDROCK` (AWS's own variable for a Bedrock API key; not `AWS_SECRET_ACCESS_KEY`, which is half of an IAM key pair)

Keys are NOT stored in `settings.json`. `GetKey(provider)` / `SetKey` / `DeleteKey` / `GetKeyStatus` are the API surface.

**AWS Bedrock's connection** is not a key alone. `settings.json` → `providers` carries `aws_region`, `bedrock_auth` (`api-key`, the default, or `aws-signin`), `aws_profile` and `bedrock_routing` (`geo`, the default, or `global`); `Settings.Bedrock()` fills in the defaults and `llm.UsesAPIKey(provider, bedrockAuth)` / `Settings.UsesAPIKey` say whether a key is needed. The AWS Bedrock card saves them on change through `SetBedrock` (validated: a region-shaped code, a known mode and routing), not with the page's Save, because the routing is where the text may be processed; Reset keeps them, like the keys. In sign-in mode KeyLint reads the AWS configuration in-process (`config.LoadDefaultConfig`, the named profile or the default chain) and resolves the credentials before sending anything; in key mode it never reads `~/.aws`. `AWS_BEARER_TOKEN_BEDROCK` wins in both modes (the Anthropic SDK's adapter does that regardless, as AWS's SDKs do); the card says so in sign-in mode. `TestBedrock` is the card's Test connection: one call with the Fix model and a fixed text, only on click. `BedrockRegions` lists the regions from the build, with the geography each keeps the text in.

**Model selection:** `settings.json` carries `models` — per provider, a model for `fix` and one for `pyramidize`. An absent key or an empty string means the built-in default from `internal/llm/models.go`, so an older file needs no migration. Resolution order is request override (the CLI's `-pyramidize --provider/--model` and the eval; the app sends none since the Pyramidize choice page) → settings → default. `SettingsService.ListModels(provider)` returns what a provider can serve and never fails the caller — `ModelList.Source` says what happened instead: `live`, `empty` (answered with nothing, e.g. a fresh `ollama serve`), `unusable` (listed models, none callable at `/chat/completions`), `unreachable` and `no-credentials` (these three fall back to the curated list), or `fixed` (the Claude Code CLI, which has no endpoint to ask), or `not-asked` (OpenRouter while another provider is in use), or `known` (AWS Bedrock, which has no model list to ask: the models KeyLint knows, each checked against its AWS model card, and the picker takes any other ID or an inference profile ARN). OpenRouter's catalogue (`GET /api/v1/models`) is public and the key is never sent to it, but openrouter.ai is asked only while OpenRouter is the active provider: the settings page skips it otherwise and loads it the moment it is chosen, and `ListModels` answers `not-asked` without a request. Its `live` says nothing about the key — the UI says so — and its picker searches as you type (`kl-select`'s `filter`: typing only narrows, a choice commits, ~450 entries). `:batch` IDs (OpenRouter's asynchronous Batch API) are filtered out. There is one catalogue cache, in `internal/llm` (keyed by endpoint, not key), read by the listing and by every completion; the settings service keeps no copy, and a key change leaves it alone. The UI has a sentence per case, and the cache TTL follows the source — 10 minutes for `live`, `fixed` and `known`, 30 seconds for everything else, which all describe something the user is in the middle of fixing.

## Platform Differences

**Shortcut:** `internal/features/shortcut/service_linux.go` (build tag `!windows`) is a no-op with a `Simulate()` helper for dev. `service_windows.go` installs a `WH_KEYBOARD_LL` hook (double-tap or two independent combos, see `docs/superpowers/specs/2026-04-06-keyboard-hook-configurable-shortcuts-design.md`) and hands each detected press to `main.go` through a channel it never blocks on (the sender is the hook thread). The fix shortcut goes straight to `internal/features/silentfix` — no frontend event: it captures the source window, copies, enhances, and pastes back only into that window while it still has focus; one run at a time, guarded by a per-run token; the tray icon carries a dot while it runs (`tray.SetBusy`). A failure, or a fix it could not paste, is one silent toast (`internal/features/notify`, go-toast via the AppUserModelID registry method, so it works for the NSIS install and dev-channel builds alike; log-only off Windows); identical ones are not repeated within 30 s. A click on it emits `silentfix:open`, and `ShellComponent` routes to AI Providers or to the Fix page, which shows the reason and the text. The Pyramidize shortcut emits `shortcut:pyramidize`; `ShellComponent` navigates to `/enhance` on every route, and that page picks the shortcut up through `WailsService.takePendingPyramidize()` because the event fires before it subscribes. Saved shortcuts apply at once via `settings.OnSaved` in `main.go`; `settings.Save` refuses a shortcut change the hook could not use, and `load()` replaces unusable values from the file. `shortcut_key` is legacy and never read — up to v4.5.0-beta Ctrl+G was hard-wired.

**Clipboard:** `clipboard.Write()` on Linux requires `xsel` or `xclip` installed; failure is silently swallowed (best-effort). `clipboard.WriteRich()` (Pyramidize's Send back) adds the HTML as CF_HTML next to the text on Windows; on Linux it writes the text only.

**AI API calls:** Must go through the Go backend on Linux — WebKitGTK blocks external HTTPS fetch from the webview. Every provider call lives in `internal/llm`: `Client.Complete(ctx, Request) (Response, error)` — `Request.JSONSchema` constrains the reply and each provider enforces it in its own dialect (`response_format: json_schema` for OpenAI, OpenRouter and Ollama, `output_config.format` for Anthropic, `--json-schema` for the Claude Code CLI); a caller still parses defensively — with a registry keyed by provider ID (`openai`, `claude`, `openrouter`, `bedrock`, `claude-code`, `ollama`) and `llm.Config` supplying the API key, base URL and HTTP client. The HTTP providers are the vendor SDKs — `anthropic-sdk-go` for Claude, `openai-go` for OpenAI, for OpenRouter (`https://openrouter.ai/api`) and for Ollama through its OpenAI-compatible `/v1` endpoint; the SDKs own retries and error types. The three OpenAI-dialect providers share `completeViaOpenAI` and differ only in `chatExtras`: OpenAI sends `reasoning_effort` to the documented families, OpenRouter reads the model's catalogue entry on every call and sends a `reasoning` object as it allows (an effort the model lists; for `NoThinking`, where reasoning is not mandatory, `{effort: none}` if the model lists `none` or no levels, else `{enabled: false}`; without the catalogue the effort goes anyway and a 400 about reasoning is retried without it, and a refusal is remembered per model for 10 minutes), plus `max_tokens` clamped to the entry's `max_completion_tokens`, and no `response_format` for a model that lists neither it nor `structured_outputs`; Ollama sends none of these. A reasoning cut-off on these three providers is worded without naming a Haiku. OpenRouter's 403 is its moderation flagging the input, worded as such. **Bedrock** (`bedrock.go`) shares the Anthropic request, retry and reply handling (`messagesCall` in `anthropic.go`) and reaches bedrock-runtime `InvokeModel` through the SDK's `bedrock.WithConfig` (SigV4 or bearer); `llm.Config.Bedrock` carries region, mode, profile and routing. `BedrockInvokeID` adds the routing prefix per call (geography by region: `eu-*` → `eu`, `us-*`/`ca-*` → `us`, `ap-southeast-2/4` → `au`, `ap-northeast-1/3` → `jp`, anything else worldwide only; a known model without the geography's profile — Sonnet 5.5 in Japan — is refused before anything is sent). `bedrockModels` stands in for the missing model listing: which models take an effort and can stop reasoning, from their AWS model cards; an unknown model gets the effort and one retry without it on a 400. No `output_config.format` is ever sent. Its 403 is worded by the `X-Amzn-Errortype` class (model access / rejected key or credentials / expired), naming model and region; a sign-in that cannot be used is `ErrAWSSignIn`, worded with the command to run (`aws sso login`, `aws sts get-caller-identity`), the AWS SDK's own text only at Debug. For those HTTP providers, a provider's error body never reaches an error string (#41): errors carry provider, status and a reason KeyLint worded, and the body goes to `Debug` through `Redact`. The `claude-code` provider still puts CLI output into its errors — that path was out of scope for #41. The SDK clients take no configuration from the environment: Anthropic via `WithoutEnvironmentDefaults`, OpenAI — which has no equivalent — via an always-explicit base URL plus deletion of the headers `OPENAI_ORG_ID`/`OPENAI_PROJECT_ID`/`OPENAI_CUSTOM_HEADERS` would set, so no `*_BASE_URL` can redirect a request and no environment header rides along. That covers what those SDK versions read; an SDK bump can add a variable, which is why the tests assert on what reaches an httptest server rather than on the options we pass. The SDKs also reject a 2xx that is not `application/json`, which the hand-rolled clients tolerated. Features (`enhance`, `pyramidize`) build a `Request` and never touch a provider API directly.

## Dark Mode

`<html class="app-dark">` set in `frontend/src/index.html` before Angular bootstraps — eliminates flash. It must be `<html>`: KeyLint's `--kl-*` tokens (`frontend/src/theme.css`) live on `:root`, several as aliases of others, and an alias resolves where it is declared — a theme class on `<body>` is how PrimeNG's selects, tabs and disabled fields once rendered light (#28). `theme.css` also sets `color-scheme: dark` so native controls and scrollbars draw dark. `ShellComponent.applyTheme()` never removes the class: only the dark theme is styled, so `theme_preference` is not read until the light theme lands (#24, #25).

## Routes

```
/welcome              → WelcomeWizardComponent (first-run guard redirects here)
/ → /fix              → FixComponent (default; manual fix — the shortcut's silent fix runs in ShellComponent)
/enhance              → TextEnhancementComponent (manual input/output)
/settings             → SettingsComponent
/dev-tools            → DevToolsComponent (dev mode only)
```

`firstRunGuard` in `app.routes.ts` checks `WailsService.isFirstRun()` before allowing shell routes.
